COMPENSATING-CONTROL CLASSIFICATION
======================================================================

Classify relevant controls as:

`closes_path`

A mandatory control applicable to the same:

- trigger;
- state;
- actor;
- branch;
- security object;
- security objective;

that prevents the adverse outcome or fully restores the required invariant
before a material security failure becomes possible.

`bounds_impact`

Limits:

- severity;
- duration;
- repetition;
- scope;

but leaves the adverse branch available.

`supports_recovery`

Restores service or protocol state only after the adverse behavior has already
occurred.

`irrelevant`

Does not govern the same branch or security effect.

`uncertain`

Applicability or effect cannot be established.

ONLY `closes_path` can fully compensate for a branch that would otherwise
produce a material security failure.

The following do NOT automatically close a weakness:

- optional safeguards;
- safe sibling branches;
- later retries;
- eventual recovery;
- unrelated validation;
- implementation-specific behavior.

For a control to be security-equivalent, check:

- same security object;
- same actor or enforcing authority;
- same relevant state;
- same trigger;
- sufficient modality;
- sufficient timing.

A later safeguard does not automatically compensate for an earlier irreversible
security effect.

Freeze the reconstructed local-rule and dependency model before proceeding to
the security assessment.

If later evidence requires a factual correction, apply that correction
consistently to every affected assessment and finding.

- mandatory same-branch closing control;

`adverse`
----------------------------------------------------------------------

security consequence.

----------------------------------------------------------------------
